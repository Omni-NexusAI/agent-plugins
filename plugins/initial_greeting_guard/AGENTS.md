# Initial Greeting Guard DOX

Own only provenance marking of newly created native synthetic welcome records
and their omission from model-facing history through supported extension hooks.
Keep native source, visible welcome, genuine greetings, original stored content,
old unmarked chats, tool receipts and all unrelated plugins unchanged.

Support only inspected initializer source path/hash and exact native metadata.
The legacy initializer requires empty initial-user metadata; reviewed v2.15
requires exactly initial_seed=true. Preserve that native marker when adding the
plugin tag. Do not infer provenance from words, roles or non-LLM metadata alone.
Existing hash/ID/content/sequence checks remain required before filtering.
The supported own-plugin change end hook refreshes only this plugin namespace;
it never clears unrelated modules or changes user history. This permits hot
activation when host-side bind-mount writes do not reach native file watchers.

Verify against the real native initializer/history/model serializer without
network first. Live task continuity remains a separate gate; this plugin is
not a universal task-loss repair. Keep runtime toggles/cache/config out of source.
